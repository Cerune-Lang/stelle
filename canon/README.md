# Stelle — Canon の運用ルール

このディレクトリは、**確定した設定の根拠**と、AI を含む共同制作時のレビュー規則を扱います。
ここに書かれた運用ルールは新しい登場人物・事件・世界の真実を創作するものではありません。

## 決定権と状態

- **提案 (proposal)**: AI や共同開発者が提示したアイデア。物語上の事実ではない。
- **承認済み (approved canon)**: 物語の監修者が明示的に承認した事実。本文・実装・翻訳の共通根拠。
- **実装済み (implemented)**: プログラムや文章へ反映された状態。実装済みでも、設定が承認されたことにはならない。
- 承認前に提案を事実として扱わない。明示されていない秘密、動機、恋愛関係、年齢、出自を確定させない。
- 既存の承認済み設定と衝突する場合、**勝手に補正せず監修者に差分を提示**する。
- 設定改訂と、物語の中で人物が変化することを区別する。前者は監修者の承認が必要。

## 今の制作原則

- 主人公は、恋愛・冒険・生活・ファンタジー世界での所属や仕事など、生き方を選べる。
- 世界の大きな出来事は、主人公が関わらなくても起こり得る。主人公の参加を強制しない。
- NPC にも固有の意思、人間関係、人生があり、主人公の不在中にも変化する。
- 共通の重要イベントと、誰とどう関わったかによって変わる個別シーンを分ける。
- 恋愛、性格、会話、世界設定は、監修者の承認を得ずに具体化しない。

## 今後キャラクター設定を記録するときの最低条件

各人物の設定には、原則として以下を分けて記録する。

1. **Core**: 根本的な価値観・変わらない事実（作者による設定改訂を除く）
2. **Arc**: その期間に持つ信念・目標・葛藤と、それらを変化させる承認済みイベント
3. **State**: 一時的な感情、関係性、経験に応じた状況
4. **Knowledge / Belief**: 何を知っているか、何を事実だと信じているか、知った経路
5. **Constraints**: 時系列、所在地、未発生イベント、未公開情報、禁止される唐突な変化

登場人物の矛盾した行動そのものは禁止しない。信念に反する行動なら、
その人物にとって納得できる動機・葛藤・結果を描き、必要なら監修を受ける。

## 実装との境界

- `src/relationship.ceru` は **メカニクスのみ**。キャラ ID や数値には正史の意味を与えない。
- 関係性や世界の変化は、承認されたイベントを介してゲーム状態へ反映する。
- AI の文章レビューは補助手段であり、人格や動機の意味的な一貫性を完全には証明できない。
- ゲーム内テキストは表示層と i18n に置き、イベント ID / 状態遷移を言語から独立させる。
